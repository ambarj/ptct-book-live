Why Can’t We Solve All Equations?

Throughout Chapter 3, you wielded powerful formulas — \( x = A\cos(\omega t + \varphi) \) for the harmonic oscillator, exponential decay \( e^{-\gamma t} \) for damping, steady-state amplitudes for driven systems. Every differential equation you met had a neat, closed-form answer.

Here’s the uncomfortable truth: you’ve been solving the easy ones. Most differential equations that arise in real physics — from planetary orbits to turbulent flow to protein folding — have no closed-form solution. Not because we haven’t been clever enough, but because the solutions literally cannot be written in terms of functions you know.

This isn’t a failure of mathematics. It’s a call to build better tools. In this chapter, you’ll learn to solve any differential equation — not with algebra, but with computation. First, let’s see exactly where pen-and-paper methods hit a wall.

Learning Objectives
  • Recognize which differential equations have analytical solutions and which don’t
  • Understand that nonlinearity is what makes most physics equations unsolvable
  • See how the small-angle approximation breaks down for the real pendulum
  • Visualize the core idea behind numerical methods: following slopes step by step

Your analytical toolkit has three main tricks: direct integration (when the right-hand side doesn’t involve the unknown), separation of variables (when you can isolate \(x\) and \(t\) on different sides), and the characteristic equation (for linear ODEs with constant coefficients, like the SHO). These cover a surprising range of problems — but they all rely on one crucial property: linearity.

The verdict

Half the equations — including some of the most important in physics — have no closed-form solution. And this is a generous selection. In the wild, unsolvable equations outnumber solvable ones by a vast margin.

Key Insight

What makes an equation unsolvable? In every case above, the culprit is the same: nonlinearity. When the unknown variable appears inside \(\sin\theta\), or as \(x^3\), or multiplied by itself in the damping term, our algebraic tricks break down. Linear equations are special — and nature is not usually that generous.

Reflect on what you discovered in the Equation Sorter.

What do the three unsolvable equations in the sorter have in common?
Explanation: The unsolvable equations all have the unknown variable (\(\theta\) or \(x\)) appearing inside a nonlinear function: \(\sin\theta\), \(x^3\), and \(x^2\dot{x}\). The solvable equations only have \(x\) appearing linearly (multiplied by a constant, or not at all).
The property that makes the SHO equation \(\ddot{x} + \omega^2 x = 0\) solvable by the characteristic equation method is that it is in \(x\).
Explanation: The equation is linear in \(x\): the unknown and its derivatives appear only to the first power, never inside nonlinear functions. This linearity is exactly what lets us use the characteristic equation \(r^2 + \omega^2 = 0\) to find solutions.
Which of these make an ODE nonlinear? (Select all that apply.)
Explanation:
  • \(\sin(x)\), \(\cos(x)\): Yes — these are nonlinear functions of the unknown.
  • Second derivatives: No — \(\ddot{x}\) is still linear in \(x\). The SHO has \(\ddot{x}\) and is perfectly solvable.
  • \(x^2\), \(x\dot{x}\): Yes — products of the unknown with itself break linearity.
  • Time-dependent coefficients: No — \(t^2\) is a known function, not the unknown. An equation like \(\dot{x} = t^2\) is still linear (and directly integrable).

So we can’t solve most equations on paper. What can we do?

Here’s the key insight: even when we can’t find a formula for the solution, we always know the slope. A first-order ODE \(\dot{x} = f(x, t)\) tells us: “wherever you are, this is the direction to go.” A slope field draws that direction at every point. A numerical method simply follows the arrows, one small step at a time.

Key Insight

Numerical methods don’t solve differential equations — they follow them. At each point, they read the slope from \(f(x, t)\), take a small step in that direction, and repeat. No algebra, no tricks — just arithmetic. The smaller your step, the more faithfully you follow the true path. In the next section, we’ll turn this idea into a precise recipe: Euler’s method.

Which statements about numerical methods are TRUE? (Select all that apply.)
Explanation:
  • Step by step: True — that’s exactly how they work: compute slope, step, repeat.
  • Exact answers: False — numerical methods give approximations that get better with smaller steps.
  • Only need \(f\) and ICs: True — you never need to “solve” the equation. You just evaluate \(f(x,t)\) at each step.
  • Need the analytical solution: False — the whole point is that no analytical solution exists!

Python Code Examples

Python 
import numpy as np
from scipy.integrate import solve_ivp
import plotly.graph_objects as go

# Non-dimensionalized pendulum: theta'' = -sin(theta)
def pendulum(t, y):
    return [y[1], -np.sin(y[0])]

# Small-angle (SHO): theta'' = -theta
def sho(t, y):
    return [y[1], -y[0]]

theta0 = np.radians(90)   # Try 30, 90, 150
t_span = (0, 20)
t_eval = np.linspace(0, 20, 1000)

sol_full = solve_ivp(pendulum, t_span, [theta0, 0], t_eval=t_eval)
sol_sho  = solve_ivp(sho,     t_span, [theta0, 0], t_eval=t_eval)

fig = go.Figure()
fig.add_trace(go.Scatter(
    x=sol_full.t, y=np.degrees(sol_full.y[0]),
    mode='lines', name='Full pendulum',
    line=dict(color='#00f3ff', width=2)))
fig.add_trace(go.Scatter(
    x=sol_sho.t, y=np.degrees(sol_sho.y[0]),
    mode='lines', name='Small-angle approx',
    line=dict(color='#ff00ff', width=2, dash='dash')))

fig.update_layout(
    template='plotly_dark',
    title='Pendulum: Exact vs Small-Angle',
    xaxis=dict(title='Time (τ)', range=[0, 20],
        gridcolor='#2a2f4a', zerolinecolor='#808080',
        linecolor='#808080'),
    yaxis=dict(title='Angle (degrees)', range=[-180, 180],
        gridcolor='#2a2f4a', zerolinecolor='#808080',
        linecolor='#808080'))
fig.show()
Python 
import numpy as np
import plotly.graph_objects as go

# ODE: dx/dt = sin(x + t) — no closed-form solution!
def f(x, t):
    return np.sin(x + t)

fig = go.Figure()

# Draw slope field as short line segments
L = 0.18
t_ticks, x_ticks = [], []
for t in np.arange(0, 8.5, 0.5):
    for x in np.arange(-4, 4.5, 0.5):
        m = f(x, t)
        norm = np.sqrt(1 + m**2)
        dt = L / norm
        dx = L * m / norm
        t_ticks.extend([t - dt, t + dt, None])
        x_ticks.extend([x - dx, x + dx, None])

fig.add_trace(go.Scatter(
    x=t_ticks, y=x_ticks,
    mode='lines', line=dict(color='#555', width=1),
    showlegend=False))

# Euler solution with small h for "truth"
h = 0.01
t_sol, x_sol = [0.0], [1.0]
while t_sol[-1] < 8:
    x_sol.append(x_sol[-1] + h * f(x_sol[-1], t_sol[-1]))
    t_sol.append(t_sol[-1] + h)

fig.add_trace(go.Scatter(
    x=t_sol, y=x_sol, mode='lines',
    name='Solution from x(0) = 1',
    line=dict(color='#00f3ff', width=2)))

fig.update_layout(
    template='plotly_dark',
    title='Slope Field: dx/dt = sin(x + t)',
    xaxis=dict(title='t', range=[0, 8],
        gridcolor='#2a2f4a', zerolinecolor='#808080',
        linecolor='#808080'),
    yaxis=dict(title='x', range=[-4, 4],
        gridcolor='#2a2f4a', zerolinecolor='#808080',
        linecolor='#808080'))
fig.show()
