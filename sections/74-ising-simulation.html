Ising Model Simulation & Results

You have the algorithm. Now let’s use it. This section runs production-quality Metropolis simulations of the 1D Ising model, computes thermal averages, and compares with the exact analytical solution. You’ll also learn two practical skills every MC practitioner needs: detecting equilibration and measuring autocorrelation.

Learning Objectives
  • Run long Metropolis simulations and compute thermal averages \( \langle E \rangle \) and \( \langle |M| \rangle \) after discarding burn-in
  • Compare MC results with the exact 1D Ising solution \( \langle E \rangle / NJ = -\tanh(J/k_BT) \)
  • Determine the burn-in period: how many steps before measurements are valid
  • Understand autocorrelation: consecutive MC samples are correlated, reducing effective sample size

Exact 1D Ising Solution:

$$ \frac{\langle E \rangle}{NJ} = -\tanh\!\left(\frac{J}{k_BT}\right) $$

This exact result (derivable via transfer matrix) serves as a benchmark. If your MC simulation reproduces this curve, the algorithm is working correctly.

Effective Sample Size

If the autocorrelation time is \( \tau_{\text{auto}} \) steps, then out of \( N_{\text{steps}} \) total MC steps, only \( N_{\text{eff}} \approx N_{\text{steps}} / (2\tau_{\text{auto}}) \) are independent. The true statistical error is \( \sigma / \sqrt{N_{\text{eff}}} \), not \( \sigma / \sqrt{N_{\text{steps}}} \). Ignoring autocorrelation underestimates your error bars!

Run at T/J = 0.5. The autocorrelation function \( C(k) \) decays slowly. What does this mean practically?
Explanation: Slow decay of \( C(k) \) means the chain moves sluggishly through configuration space. Sample \( n \) is very similar to sample \( n+1 \). To get independent measurements, you must skip many steps between samples. This is the critical slowing down at low T.
Now run at T/J = 3.0. How does the autocorrelation compare?
Explanation: At high T, the acceptance rate is high and the chain moves freely. Each step significantly changes the configuration, so \( C(k) \) drops to zero within a few steps. Nearly every sample is independent — ideal for MC.

Explanation: Using \( N_{\text{steps}} \) instead of \( N_{\text{eff}} \) in the denominator makes the error bar too small — you underestimate the true uncertainty. import numpy as np
import plotly.graph_objects as go
from plotly.subplots import make_subplots

def metropolis_1d(N, T, n_steps):
    spins = np.random.choice([-1, 1], N)
    E = -np.sum(spins[:-1] * spins[1:])
    energies, mags = [], []
    for _ in range(n_steps):
        i = np.random.randint(N)
        dE = 0
        if i > 0:   dE += 2 * spins[i] * spins[i-1]
        if i < N-1: dE += 2 * spins[i] * spins[i+1]
        if dE <= 0 or np.random.random() < np.exp(-dE/T):
            spins[i] *= -1
            E += dE
        energies.append(E)
        mags.append(np.abs(np.sum(spins)) / N)
    return np.array(energies), np.array(mags)

# Temperature sweep
N = 50
Ts = np.linspace(0.3, 5, 25)
mc_E, mc_M = [], []
for T in Ts:
    E, M = metropolis_1d(N, T, 10000)
    mc_E.append(np.mean(E[2000:]) / N)
    mc_M.append(np.mean(M[2000:]))

fig = make_subplots(1, 2, subplot_titles=['⟨E⟩/N', '⟨|M|⟩/N'])
fig.add_trace(go.Scatter(x=Ts, y=mc_E, mode='markers',
    marker=dict(color='#00f3ff', size=8), name='MC'), row=1, col=1)
fig.add_trace(go.Scatter(x=Ts, y=-np.tanh(1/Ts), mode='lines',
    line=dict(color='white', dash='dash'), name='Exact'), row=1, col=1)
fig.add_trace(go.Scatter(x=Ts, y=mc_M, mode='markers',
    marker=dict(color='#ff006e', size=8), name='MC'), row=1, col=2)

fig.update_layout(template='plotly_dark', height=400, width=900)
for col in [1,2]:
    fig.update_xaxes(title='T/J', zerolinecolor='#808080', row=1, col=col)
fig.update_yaxes(title='⟨E⟩/NJ', range=[-1.1,0.1],
    zerolinecolor='#808080', row=1, col=1)
fig.update_yaxes(title='⟨|M|⟩/N', range=[0,1.05],
    zerolinecolor='#808080', row=1, col=2)
fig.show()

import numpy as np
import plotly.graph_objects as go

def autocorrelation(data, max_lag=200):
    """Compute normalized autocorrelation function."""
    n = len(data)
    mean = np.mean(data)
    var = np.var(data)
    if var < 1e-10: return np.zeros(max_lag)
    C = np.zeros(max_lag)
    for k in range(max_lag):
        C[k] = np.mean((data[:n-k] - mean) * (data[k:] - mean)) / var
    return C

N, n_steps = 50, 20000
fig = go.Figure()
colors = ['#00f3ff', '#ffbe0b', '#ff006e']

for T, color in zip([0.5, 1.0, 3.0], colors):
    E, _ = metropolis_1d(N, T, n_steps)
    C = autocorrelation(E[2000:], 300)  # skip burn-in
    fig.add_trace(go.Scatter(
        y=C, mode='lines', line=dict(color=color, width=2),
        name=f'T/J = {T}'))

fig.add_trace(go.Scatter(
    x=[0, 300], y=[0, 0], mode='lines',
    line=dict(color='#808080', dash='dot'), showlegend=False))

fig.update_layout(template='plotly_dark',
    xaxis=dict(title='Lag k (MC steps)', zerolinecolor='#808080'),
    yaxis=dict(title='C(k)', range=[-0.2, 1.05],
        zerolinecolor='#808080'),
    height=400, width=550)
fig.show()
