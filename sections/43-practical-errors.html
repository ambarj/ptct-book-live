Error Analysis in Practice

Every numerical method introduces error, but not all errors are the same. When you solve a differential equation with Euler's method, you're fighting on two fronts: truncation error from the algorithm, and round-off error from the computer. Understanding both is essential for trusting your numerical results.

Learning Objectives
  • Distinguish between truncation error and round-off error
  • Verify that Euler's method converges as \( O(h) \) by testing at multiple step sizes
  • Understand why there's an optimal step size — too small is also bad
  • Use Richardson extrapolation to get better answers from cheap solvers

Total Error:

$$ \text{Total Error} = \underbrace{\text{Truncation Error}}_{\text{from the algorithm}} + \underbrace{\text{Round-off Error}}_{\text{from the computer}} $$

Truncation error comes from replacing the exact derivative with a finite-difference approximation. For Euler's method, we use \( y_{n+1} = y_n + h\,f(t_n, y_n) \), which ignores higher-order terms in the Taylor expansion. This error scales as \( O(h) \) — halve the step, halve the error.

Round-off error comes from the computer storing numbers with finite precision (about 15-16 digits in double precision). Each step adds a tiny rounding error, and with \( N = T/h \) steps, these accumulate. Smaller \( h \) means more steps means more accumulated round-off.

⚠️
The Paradox:

Making \( h \) smaller reduces truncation error but increases round-off error. There's an optimal step size where total error is minimized!

Measuring Convergence Order

How do you verify that your code converges at the expected rate? Run the solver at multiple step sizes, measure the error at a fixed time, and plot error vs \( h \) on a log-log scale. The slope tells you the convergence order.

Convergence Test:

$$ \text{error}(h) \propto h^p \quad\Longrightarrow\quad \log(\text{error}) = p\,\log(h) + \text{const} $$

For Euler: \( p = 1 \). For RK2: \( p = 2 \). For RK4: \( p = 4 \).

Richardson Extrapolation

If your method has error \( \propto h^p \), you can combine two runs at step sizes \( h \) and \( h/2 \) to cancel the leading error term:

$$ y_{\text{better}} = \frac{2^p \, y(h/2) - y(h)}{2^p - 1} $$

For Euler (\( p = 1 \)): \( y_{\text{better}} = 2\,y(h/2) - y(h) \). This effectively gives you second-order accuracy from a first-order method — for free!

Choosing the Right Step Size

In practice, you need to balance accuracy against computational cost. Smaller \( h \) gives better accuracy, but requires more steps (and more CPU time). The key question: how small is small enough?

Why RK4 Wins

For 6-digit accuracy, Euler needs millions of steps while RK4 needs only hundreds. Even though each RK4 step costs 4× more function evaluations than Euler, the \( O(h^4) \) convergence rate crushes Euler's \( O(h) \). This is why RK4 is the standard workhorse in computational physics.

Python 

import numpy as np
import plotly.graph_objects as go

def euler(f, y0, T, h):
    """Euler method: returns (t_array, y_array)."""
    t = np.arange(0, T + h/2, h)
    y = np.zeros(len(t))
    y[0] = y0
    for i in range(len(t) - 1):
        y[i+1] = y[i] + h * f(t[i], y[i])
    return t, y

# Test equation: dy/dt = -y, exact: y = exp(-t)
f = lambda t, y: -y
exact = lambda t: np.exp(-t)

# Run at multiple step sizes
T = 5.0
h_values = np.logspace(-4, 0, 30)  # h from 0.0001 to 1
errors = []

for h in h_values:
    t, y = euler(f, 1.0, T, h)
    err = abs(y[-1] - exact(T))
    errors.append(err)

# Log-log plot
fig = go.Figure()
fig.add_trace(go.Scatter(x=h_values, y=errors,
    mode='markers+lines', name='Euler error',
    line=dict(color='#00f3ff', width=2)))

# Reference slope-1 line
fig.add_trace(go.Scatter(x=[1e-4, 1], y=[1e-4, 1],
    mode='lines', name='O(h) reference',
    line=dict(color='#808080', dash='dash')))

fig.update_layout(
    template='plotly_dark',
    xaxis=dict(type='log', title='Step size h',
               gridcolor='#2a2f4a', linecolor='#808080'),
    yaxis=dict(type='log', title='|Error at t=T|',
               gridcolor='#2a2f4a', linecolor='#808080'),
    title='Euler Method Convergence')
fig.show()
Python 

import numpy as np

def euler(f, y0, T, h):
    t = np.arange(0, T + h/2, h)
    y = np.zeros(len(t))
    y[0] = y0
    for i in range(len(t) - 1):
        y[i+1] = y[i] + h * f(t[i], y[i])
    return t, y

f = lambda t, y: -y
exact_val = np.exp(-5.0)  # exact at T=5
T = 5.0

print(f"Exact y(T=5) = {exact_val:.10f}\n")
print(f"{'h':>10s}  {'y_Euler':>12s}  {'y_Rich':>12s}  {'Err_Euler':>10s}  {'Err_Rich':>10s}")
print("-" * 62)

for h in [0.5, 0.2, 0.1, 0.05, 0.02, 0.01]:
    _, y1 = euler(f, 1.0, T, h)      # run at h
    _, y2 = euler(f, 1.0, T, h/2)    # run at h/2

    y_euler = y1[-1]
    y_rich = 2 * y2[-1] - y1[-1]     # Richardson for p=1

    err_euler = abs(y_euler - exact_val)
    err_rich = abs(y_rich - exact_val)

    print(f"{h:10.4f}  {y_euler:12.8f}  {y_rich:12.8f}  {err_euler:10.2e}  {err_rich:10.2e}")
