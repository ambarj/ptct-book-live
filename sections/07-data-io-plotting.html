Hello Data: Reading, Plotting, Saving

Every physics experiment begins and ends with data. Before you can extract the acceleration due to gravity from a falling ball or measure the half-life of a radioactive sample, you need to know how to handle numbers: generate them, visualize them, and save them for later. This section builds those foundational skills.

Learning Objectives
  • Understand how continuous functions become discrete data through sampling
  • See how noise affects data and how more samples help
  • Learn when to use linear vs logarithmic scales
  • Master the basic workflow: generate → plot → analyze → save

From Functions to Data

A photograph captures continuous reality as discrete pixels. Data works the same way — it's a continuous function sampled at specific points. How many samples do you need before the data faithfully represents the underlying function? Let's find out.

Interactive: From Function to Data
Key Insight

The gray dashed line is the "truth" — the continuous function. The cyan dots are what you'd actually measure in an experiment. With too few samples, the data can be misleading. With enough samples, the data tells the whole story. This tension between continuous reality and discrete measurement is at the heart of experimental physics.

Which function requires the most sample points to faithfully represent? Try each one and compare.
Explanation
The sine function oscillates, meaning it changes direction multiple times across the range. Each oscillation needs several sample points to be captured. The Gaussian and exponential are smooth, single-featured functions that need far fewer points. This connects to a deep idea in signal processing: the Nyquist theorem says you need at least two samples per oscillation period to reconstruct a signal.

Real Data Is Noisy

No measurement is perfect. Every sensor adds noise, every experiment has fluctuations. The question isn't whether your data is noisy — it's whether you can still see the signal through the noise. How much noise can you tolerate? How does the number of data points help?

Interactive: Noise Explorer
Key Insight

Notice how increasing the number of data points makes the underlying function shape emerge even through heavy noise. This is the essence of statistics: individual measurements are unreliable, but patterns appear when you collect enough of them. In Chapter 2.3, we'll quantify this precisely with error bars.

Explanation

  • Reducing noise: Obviously helps, but you can't always control this in a real experiment.
  • Changing colors: No. Presentation changes don't affect the information in the data.
  • Knowing the expected shape: Yes! If you have a theoretical model (like "this should be Gaussian"), you can fit that model to noisy data. This is the idea behind curve fitting, which we'll explore in Section 2.5.
You have 10 data points with 40% noise and need to see the function shape more clearly. You can either collect 10× more data or reduce noise to 10%. Both cost the same effort. Which is generally more effective?
Explanation
Try both in the explorer! With 100 points at 40% noise, the shape is visible but fuzzy. With 10 points at 10% noise, the shape is much cleaner. Reducing noise is generally more powerful because statistical averaging only reduces uncertainty as \( 1/\sqrt{N} \) — you need 4× more data to halve the noise, and 16× to cut it to a quarter (40% → 10%, as here). But improving the apparatus cuts noise directly. In practice, you do both.

Choosing the Right Scale

Sometimes the most important thing you can do with data is choose the right way to look at it. A plot that seems featureless on a linear scale can reveal beautiful structure on a logarithmic scale. Physicists switch between scales constantly — it's one of the most practical tricks in the toolbox.

Interactive: Linear vs Log Scale
Key Insight

Exponential functions become straight lines on a semi-log plot (log y vs. linear x).
Power law functions become straight lines on a log-log plot (log y vs. log x).
This is incredibly useful: if you plot your data and it looks like a straight line on one of these scales, you've identified the functional form. We'll use this trick repeatedly when fitting data in Section 2.5.

Test Your Understanding

Switch between scales for each function to answer these questions.

Select Exp. Decay and try all three scales. On which scale does the data appear as a straight line?
Explanation
The exponential \( y = 10 \, e^{-0.3x} \) becomes a straight line on a semi-log plot. Why? Taking the log: \( \ln y = \ln 10 - 0.3x \), which is linear in \( x \). The slope of this line gives the decay constant (0.3), and the y-intercept gives the amplitude 10 (in \( \ln y \) coordinates the intercept reads \( \ln 10 \approx 2.3 \)). This is how physicists extract decay rates from experimental data.
A dataset, when plotted on a log-log scale, appears as a straight line. This means the underlying relationship is:
Explanation
For a power law \( y = A x^n \), taking the log of both sides: \( \log y = \log A + n \log x \). This is linear in \( \log x \) with slope \( n \) and intercept \( \log A \). Verify this by selecting "Power Law" and switching to log-log! The slope tells you the exponent directly.

Explanation
On a semi-log plot, the exponential \( y = 10 \, e^{-0.3x} \) appears as a straight line sloping downward (since the exponent is negative).

At \( x = 0 \): \( y = 10 \, e^{0} = 10 \). At \( x = 10 \): \( y = 10 \, e^{-3} \approx 0.50 \).

The function has decayed by a factor of \( 10 / 0.5 = 20 \) over this range. Being able to read values off a log-scale plot is an essential experimental skill — notice how the log scale spreads out the small values, making 0.5 easy to read even though it would be squished near zero on a linear plot.

Python Code Examples

Here's the Python code that reproduces what the explorers above do. Run these in a Jupyter notebook to build your own data workflows.

Python 
import numpy as np
import plotly.graph_objects as go

# The "true" function (continuous)
x_smooth = np.linspace(-3, 3, 200)
y_smooth = np.exp(-x_smooth**2)    # Gaussian

# Sample it at discrete points (like real data)
n_points = 20
x_data = np.linspace(-3, 3, n_points)
y_data = np.exp(-x_data**2)

# Plot both
fig = go.Figure()
fig.add_trace(go.Scatter(
    x=x_smooth, y=y_smooth, mode='lines',
    name='True function',
    line=dict(color='gray', dash='dot', width=1)))
fig.add_trace(go.Scatter(
    x=x_data, y=y_data, mode='markers',
    name=f'Data ({n_points} points)',
    marker=dict(color='#00f3ff', size=8)))

fig.update_layout(
    template='plotly_dark',
    title='From Function to Data',
    xaxis_title='x', yaxis_title='f(x)',
    xaxis=dict(range=[-3.5, 3.5], zerolinecolor='#808080'),
    yaxis=dict(range=[-0.2, 1.3], zerolinecolor='#808080'))
fig.show()
Python 
import numpy as np
import plotly.graph_objects as go

# Generate clean data
n_points = 50
x = np.linspace(-3, 3, n_points)
y_clean = np.exp(-x**2)

# Add noise: 20% of the function's amplitude
noise_level = 0.20
amplitude = y_clean.max() - y_clean.min()
noise = noise_level * amplitude * np.random.uniform(-1, 1, size=n_points)
y_noisy = y_clean + noise

# Reference curve
x_ref = np.linspace(-3, 3, 200)
y_ref = np.exp(-x_ref**2)

fig = go.Figure()
fig.add_trace(go.Scatter(
    x=x_ref, y=y_ref, mode='lines',
    name='True function',
    line=dict(color='gray', dash='dot', width=1)))
fig.add_trace(go.Scatter(
    x=x, y=y_noisy, mode='markers',
    name=f'{int(noise_level*100)}% noise',
    marker=dict(color='#ff00ff', size=7)))

fig.update_layout(
    template='plotly_dark',
    title=f'Gaussian with {int(noise_level*100)}% Noise ({n_points} points)',
    xaxis_title='x', yaxis_title='f(x)',
    xaxis=dict(range=[-3.5, 3.5], zerolinecolor='#808080'),
    yaxis=dict(range=[-0.8, 1.8], zerolinecolor='#808080'))
fig.show()
Python 
import numpy as np
import plotly.graph_objects as go
from plotly.subplots import make_subplots

# Exponential decay
x = np.linspace(0.1, 15, 80)
y = 10 * np.exp(-0.3 * x)

# Side-by-side: linear vs semi-log
fig = make_subplots(rows=1, cols=2,
    subplot_titles=['Linear Scale', 'Semi-log Scale'])

for col in [1, 2]:
    fig.add_trace(go.Scatter(
        x=x, y=y, mode='lines+markers',
        line=dict(color='#00f3ff', width=2),
        marker=dict(size=4), showlegend=False),
        row=1, col=col)

fig.update_yaxes(type='log', row=1, col=2)
fig.update_layout(
    template='plotly_dark',
    title='Exponential Decay: Linear vs Semi-log',
    height=400)
fig.show()

# Key insight: on semi-log, exponential = straight line
# slope = -0.3 (the decay constant)
# y-intercept = ln(10) ≈ 2.3
