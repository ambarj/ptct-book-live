RK4 for Escape Velocity

In Sections 4.14–4.15 we derived the dimensionless ODE and learned that \( V_0 = \sqrt{2} \) is the escape threshold. Energy conservation told us whether escape happens — but not when or how. How long does it take to reach altitude \( X = 5 \)? What does the trajectory look like in time? For this, we need to integrate.

Learning Objectives
  • Solve the dimensionless escape ODE \( \ddot{X} = -1/X^2 \) using RK4 to get actual trajectories \( X(T) \)
  • Validate RK4 against the exact critical solution \( X(T) = (1 + \tfrac{3}{2}\sqrt{2}\,T)^{2/3} \)
  • Use numerical bisection to find escape velocity to arbitrary precision
  • Monitor energy conservation \( E = \tfrac{1}{2}V^2 - 1/X \) as a check on numerical accuracy

The system to solve:

$$ \frac{dX}{dT} = V, \qquad \frac{dV}{dT} = -\frac{1}{X^2} $$

with \( X(0) = 1 \), \( V(0) = V_0 \). This is a 2D first-order system — exactly what RK4 handles.

At the critical speed \( V_0 = \sqrt{2} \), there is an exact analytical solution:

$$ X(T) = \left(1 + \tfrac{3}{2}\sqrt{2}\,T\right)^{2/3} $$

We'll use this to validate our numerical solver before trusting it on cases where no analytical solution exists.

We know the escape velocity is \( V_0 = \sqrt{2} \) from energy conservation. But what if we didn't? We could discover it numerically using bisection: run RK4, check if the projectile escapes, and narrow the bracket.

The bisection method checks whether the projectile reaches X > 10 by T = 20. Why is this a valid proxy for "escape"?
Explanation: A bound trajectory has a turning point at \( X_{\max} = 2/(2 - V_0^2) \). Near the escape threshold this grows without bound — at V₀ = 1.4 it is already ≈ 50 — which is why crossing a fixed distance is NOT enough to declare escape: a barely-bound projectile coasts past any threshold before falling back (at V₀ = 1.3, X_max ≈ 6.5 and it turns around quickly). The solver therefore also checks the local escape-speed condition \( v^2 \ge 2/x \) once the projectile is far away, and declares "bound" the moment the velocity turns negative.
Why is bisection useful even though we already know V₀ = √2 analytically? (Select all)
Explanation:
  • The analytical formula √2 is exact — bisection can't beat it for this problem.
  • ✓ When we add air resistance (Section 4.17), there's no analytical escape velocity. Bisection + RK4 is the only way.
  • ✓ Reproducing √2 numerically confirms our code is correct. This is a fundamental validation strategy: test on known problems before tackling unknown ones.
  • Bisection requires many RK4 runs — it's slower than evaluating √2. Speed isn't the point; generality is.

Which are good practices when solving ODEs numerically? (Select all)
Explanation:
  • ✓ Energy conservation is a powerful diagnostic. If E drifts, the step size is too large.
  • The smallest h is wasteful — you need "small enough," not "smallest possible." Choose h by checking that the answer doesn't change when you halve it.
  • Code running without errors doesn't mean the answer is correct. Numerical errors are silent — they don't crash your program.
  • ✓ Validate first, trust second. We tested RK4 against X(T) = (1 + 3√2T/2)^(2/3) before trusting it on new problems. This is the scientific approach.

Python Code

Python 

import numpy as np
import plotly.graph_objects as go
from plotly.subplots import make_subplots

def rk4_step(f, y, t, h):
    k1 = f(y, t)
    k2 = f(y + h/2 * k1, t + h/2)
    k3 = f(y + h/2 * k2, t + h/2)
    k4 = f(y + h * k3, t + h)
    return y + (h/6) * (k1 + 2*k2 + 2*k3 + k4)

def escape_ode(y, t):
    X, V = y
    return np.array([V, -1/X**2])

def solve(V0, T_final=10, N=500):
    h = T_final / N
    t = np.zeros(N+1)
    Y = np.zeros((N+1, 2))
    Y[0] = [1, V0]  # X(0)=1, V(0)=V0
    for i in range(N):
        Y[i+1] = rk4_step(escape_ode, Y[i], t[i], h)
        t[i+1] = t[i] + h
        if Y[i+1, 0] < 0.01:  # crashed into planet
            break
    return t[:i+2], Y[:i+2]

# Exact solution at critical speed
def exact_critical(t):
    return (1 + 1.5 * np.sqrt(2) * t)**(2/3)

# Solve for three speeds
fig = make_subplots(rows=1, cols=2,
    subplot_titles=['X(T) Trajectory', 'Energy E(T)'])

for V0, color, label in [(1.0, '#ff6b6b', 'Bound'),
                           (np.sqrt(2), '#ffff00', 'Critical'),
                           (2.0, '#00ff9f', 'Unbound')]:
    t, Y = solve(V0)
    X, V = Y[:, 0], Y[:, 1]
    E = 0.5 * V**2 - 1/X

    fig.add_trace(go.Scatter(x=t, y=X, name=f'{label} (V₀={V0:.2f})',
        line=dict(color=color, width=2)), row=1, col=1)
    fig.add_trace(go.Scatter(x=t, y=E, name=f'E ({label})',
        line=dict(color=color, width=2), showlegend=False), row=1, col=2)

# Exact overlay
t_ex = np.linspace(0, 10, 500)
fig.add_trace(go.Scatter(x=t_ex, y=exact_critical(t_ex),
    name='Exact (critical)', line=dict(color='white', dash='dash', width=1)),
    row=1, col=1)

fig.update_layout(template='plotly_dark')
fig.update_xaxes(title='T', linecolor='#808080')
fig.update_yaxes(title='X', linecolor='#808080', row=1, col=1)
fig.update_yaxes(title='E', linecolor='#808080', row=1, col=2)
fig.show()
Python 

import numpy as np

def rk4_step(f, y, t, h):
    k1 = f(y, t)
    k2 = f(y + h/2 * k1, t + h/2)
    k3 = f(y + h/2 * k2, t + h/2)
    k4 = f(y + h * k3, t + h)
    return y + (h/6) * (k1 + 2*k2 + 2*k3 + k4)

def escape_ode(y, t):
    return np.array([y[1], -1/y[0]**2])

def escapes(V0, T=20, N=1000, X_thresh=10):
    """Return True if projectile reaches X > X_thresh by time T."""
    h = T / N
    y = np.array([1.0, V0])
    for i in range(N):
        y = rk4_step(escape_ode, y, i*h, h)
        if y[0] > X_thresh:
            return True
        if y[0] < 0.01:  # crashed
            return False
    return False

# Bisection
lo, hi = 1.0, 2.0
print(f"{'Step':>4s}  {'lo':>10s}  {'hi':>10s}  {'mid':>10s}  {'|mid-√2|':>12s}")
print("-" * 52)

for step in range(20):
    mid = (lo + hi) / 2
    err = abs(mid - np.sqrt(2))
    print(f"{step:4d}  {lo:10.6f}  {hi:10.6f}  {mid:10.6f}  {err:12.2e}")
    if escapes(mid):
        hi = mid  # too fast — lower the upper bound
    else:
        lo = mid  # too slow — raise the lower bound

print(f"\nNumerical: V0 = {(lo+hi)/2:.10f}")
print(f"Exact:     V0 = {np.sqrt(2):.10f}")

What's Next?

We've now solved the clean, drag-free escape problem. But real rockets fly through an atmosphere! In Section 4.17, we add air resistance \( F_{\text{drag}} = -\alpha\,e^{-\beta(X-1)}\,V \) to the ODE. The analytical energy trick breaks down — but RK4 and bisection handle it effortlessly. The same tools you just learned extend to problems no textbook can solve analytically.
