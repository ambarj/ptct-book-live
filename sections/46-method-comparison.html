Choosing Your Method

You now have three ODE solvers in your toolkit. Each costs a different amount per step and delivers a different accuracy. The question is no longer which is best? (RK4 wins on accuracy) but which is appropriate right now?

Learning Objectives
  • Compare Euler, RK2, and RK4 at fixed computational budget — same cost, wildly different accuracy
  • Discover the scaling laws: accuracy vs work grows as \( N^{-1} \), \( N^{-2} \), \( N^{-4} \)
  • Understand when each method is appropriate: quick look, homework, publication, long-time simulation
  • Build the habit of always verifying your solver by halving \( h \)

The cost-accuracy table:

$$ \begin{array}{lcccc} \textbf{Method} & \textbf{Evals/step} & \textbf{Local error} & \textbf{Global error} & \textbf{Order} \\[4pt] \text{Euler} & 1 & O(h^2) & O(h) & 1 \\ \text{RK2} & 2 & O(h^3) & O(h^2) & 2 \\ \text{RK4} & 4 & O(h^5) & O(h^4) & 4 \end{array} $$

The key insight: convergence order beats per-step cost. Always.

The Scaling Laws

Here is the deepest lesson: how does accuracy scale with computational work? On a log-log plot of error vs total evaluations, each method traces a straight line whose slope equals the negative of its order:

Work-accuracy scaling:

$$ \text{Euler: error} \propto N^{-1} \qquad \text{RK2: error} \propto N^{-2} \qquad \text{RK4: error} \propto N^{-4} $$

These slopes explain everything about method selection.

⚠️
The Golden Rule: Always halve h and compare.

No matter which method you choose, always run your simulation twice — once at step size \( h \) and once at \( h/2 \). If the results don't change significantly, you can trust your answer. If they do, halve again. This is the single most important practice in numerical computing.

Test Your Understanding

Use the Method Advisor to answer these questions.

For "quick exploration" (checking if your ODE setup is correct), which method is recommended and why?
Explanation: When you're first setting up a problem — checking signs, initial conditions, boundary behavior — you don't need high accuracy. Euler with a moderate h lets you see the qualitative behavior instantly. If the solution looks reasonable, then switch to RK4 for the production run.
For a long-time simulation (T = 100, energy conservation matters), what additional concern arises beyond just accuracy?
Explanation: RK4 is accurate per step, but it doesn't exactly conserve the Hamiltonian (energy). Over millions of orbits, even tiny per-step energy errors accumulate. Symplectic integrators (like Störmer-Verlet or leapfrog) preserve a nearby Hamiltonian exactly, making them the right choice for long-time Hamiltonian simulations. For most physics problems (T ~ 10–100 periods), RK4 with small enough h is excellent.
You've computed a trajectory with RK4 at h = 0.1. Which of the following should you do before trusting the result? (Select all that apply)
Explanation:
  • ✗ Never trust any numerical method blindly. RK4 is powerful but not infallible — wrong equations, stiff systems, or too-large h can still produce garbage.
  • ✓ The halving test is the gold standard: if results don't change significantly when you halve h, you can trust them.
  • ✓ Conservation laws provide independent checks. If total energy drifts by more than your error tolerance, h is too large.
  • ✓ Testing against known analytical solutions (even in simplified limits) builds confidence that your code is correct.

import numpy as np
import plotly.graph_objects as go

def euler(f, y0, T, N):
    h = T / N; t = np.linspace(0, T, N+1)
    y = np.zeros((N+1, len(y0))); y[0] = y0
    for i in range(N):
        y[i+1] = y[i] + h * np.array(f(t[i], y[i]))
    return t, y

def rk2(f, y0, T, N):
    h = T / N; t = np.linspace(0, T, N+1)
    y = np.zeros((N+1, len(y0))); y[0] = y0
    for i in range(N):
        k1 = np.array(f(t[i], y[i]))
        k2 = np.array(f(t[i] + h/2, y[i] + h/2 * k1))
        y[i+1] = y[i] + h * k2
    return t, y

def rk4(f, y0, T, N):
    h = T / N; t = np.linspace(0, T, N+1)
    y = np.zeros((N+1, len(y0))); y[0] = y0
    for i in range(N):
        k1 = np.array(f(t[i], y[i]))
        k2 = np.array(f(t[i] + h/2, y[i] + h/2 * k1))
        k3 = np.array(f(t[i] + h/2, y[i] + h/2 * k2))
        k4 = np.array(f(t[i] + h, y[i] + h * k3))
        y[i+1] = y[i] + (h/6) * (k1 + 2*k2 + 2*k3 + k4)
    return t, y

# Driven oscillator: x'' + x = cos(0.8t)
omega = 0.8
f_driven = lambda t, y: [y[1], -y[0] + np.cos(omega * t)]
exact = lambda t: (np.cos(omega*t) - omega**2*np.cos(t)) / (1 - omega**2)

# Same budget comparison
T = 20
budget = 1000  # total function evaluations
t_ex = np.linspace(0, T, 2000)

methods = {
    'Euler': (euler, budget, 1),       # N steps, 1 eval each
    'RK2':   (rk2, budget//2, 2),      # N/2 steps, 2 evals each
    'RK4':   (rk4, budget//4, 4),      # N/4 steps, 4 evals each
}

fig = go.Figure()
fig.add_trace(go.Scatter(x=t_ex, y=exact(t_ex), name='Exact',
    line=dict(color='#808080', dash='dash')))

colors = {'Euler': '#00f3ff', 'RK2': '#00ff9f', 'RK4': '#ff00ff'}
for name, (method, N, _) in methods.items():
    t, y = method(f_driven, [1, 0], T, N)
    err = np.mean(np.abs(y[:, 0] - exact(t)))
    fig.add_trace(go.Scatter(x=t, y=y[:, 0],
        name=f'{name} (err={err:.2e})', line=dict(color=colors[name])))

fig.update_layout(template='plotly_dark',
    title=f'Same budget ({budget} evals), different accuracy',
    xaxis=dict(gridcolor='#2a2f4a', linecolor='#808080'),
    yaxis=dict(gridcolor='#2a2f4a', linecolor='#808080'))
fig.show()

import numpy as np
import plotly.graph_objects as go

# (Reuse euler, rk2, rk4 from previous tab)

# Scaling analysis: error vs total evaluations
T = 10
budgets = np.logspace(2, 4.5, 30).astype(int)

euler_err, rk2_err, rk4_err = [], [], []
for N_total in budgets:
    # Euler: N_total steps × 1 eval
    _, ye = euler(f_driven, [1, 0], T, N_total)
    euler_err.append(np.mean(np.abs(ye[:, 0] - exact(np.linspace(0, T, N_total+1)))))

    # RK2: N_total/2 steps × 2 evals
    N2 = max(N_total // 2, 10)
    _, yr = rk2(f_driven, [1, 0], T, N2)
    rk2_err.append(np.mean(np.abs(yr[:, 0] - exact(np.linspace(0, T, N2+1)))))

    # RK4: N_total/4 steps × 4 evals
    N4 = max(N_total // 4, 5)
    _, y4 = rk4(f_driven, [1, 0], T, N4)
    rk4_err.append(np.mean(np.abs(y4[:, 0] - exact(np.linspace(0, T, N4+1)))))

fig = go.Figure()
fig.add_trace(go.Scatter(x=budgets, y=euler_err, name='Euler (slope ≈ -1)',
    mode='markers+lines', line=dict(color='#00f3ff')))
fig.add_trace(go.Scatter(x=budgets, y=rk2_err, name='RK2 (slope ≈ -2)',
    mode='markers+lines', line=dict(color='#00ff9f')))
fig.add_trace(go.Scatter(x=budgets, y=rk4_err, name='RK4 (slope ≈ -4)',
    mode='markers+lines', line=dict(color='#ff00ff')))

fig.update_layout(template='plotly_dark',
    xaxis=dict(type='log', title='Total function evaluations',
               gridcolor='#2a2f4a', linecolor='#808080'),
    yaxis=dict(type='log', title='Mean global error',
               gridcolor='#2a2f4a', linecolor='#808080'),
    title='Work-Accuracy Scaling Laws')
fig.show()
