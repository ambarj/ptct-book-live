Manual Parameter Exploration

Before handing control to an algorithm, you should feel how parameters affect the fit. In this section you'll manually adjust a three-parameter model, scan one parameter at a time, and even play "human optimizer" — searching for the best fit by hand. This builds the intuition that makes automated fitting (next section) feel natural rather than magical.

Learning Objectives
  • Manually adjust model parameters and observe their effect on χ²
  • Understand parameter sensitivity: which parameters matter most?
  • Perform a 1D parameter sweep and read off the minimum
  • Use coordinate descent to iteratively approach the best fit

Three-parameter model:

$$ d(t) = a + b\,t + c\,t^2 $$

Here \( a \) is an offset (should be near 0), \( b \) is an initial velocity (should be near 0 for a drop from rest), and \( c = g/2 \approx 4.9 \) captures the gravitational acceleration. With three parameters you can absorb systematic effects, but you also risk overfitting — a theme we'll revisit.

Key Insight

Notice that c (the quadratic coefficient) affects χ² most dramatically — a small change in \( c \) produces a large swing in χ². The offset \( a \) and velocity \( b \) matter less because the data spans \( t = 1 \ldots 10 \), where the \( t^2 \) term dominates. This is parameter sensitivity: some parameters are tightly constrained by the data, others are barely constrained at all.

Explanation

Try setting \( a = 10, b = -2 \). Can you still find a good fit by adjusting \( c \)? What does this tell you?
Explanation
When you set \( a = 10 \) and \( b = -2 \), the offset and linear terms partly cancel each other for intermediate \( t \), and the quadratic term can still be adjusted to approximate the data. This is parameter correlation — different parameter combinations can produce similar curves, which is why the χ² contours are elliptical.

The result is a χ² curve whose minimum gives the best value of that parameter (conditional on the fixed values of the others). Use the dropdown to choose which parameter to sweep.

Interactive: Parameter Sweep
Key Insight

The width of the χ² parabola tells you how well that parameter is constrained. A narrow parabola (like for \( c \)) means the data pins down that parameter tightly. A wide, shallow parabola (like for \( a \)) means the data barely constrains it. This is directly related to the parameter uncertainty you'll compute in automated fitting.

Sweep parameter \( c \) with \( a = 0, b = 0 \). Then sweep \( a \) with \( b = 0, c = 4.9 \). Which parabola is narrower?
Explanation
The \( c \) parabola is much narrower because the quadratic term \( c\,t^2 \) dominates the model at large \( t \). Even a small change in \( c \) produces a large model deviation, so χ² rises steeply. The offset \( a \) has much less leverage, giving a wide, shallow parabola and a larger uncertainty on \( a \).
Sweep \( b \) with \( a = 0, c = 4.9 \): the minimum sits near \( b = 0 \), as it should. Now set Fixed c = 4.0 (too small) and sweep \( b \) again. The minimum moves to a clearly positive \( b \), and the minimum χ² is much larger. What is the lesson?
Explanation
With \( c \) pinned at 4.0, the model is missing \( \approx 0.9\,t^2 \) of growth, and the sweep does its best with the tools it has: a positive \( b\,t \) partially mimics the missing quadratic. The best-fit \( b \) is biased, not because the ball had initial velocity, but because the parameters are coupled. This is exactly why one-parameter-at-a-time exploration must be iterated (fix, sweep, re-fix, re-sweep) — the coordinate-descent explorer below does precisely that.
Fix \( a = 10 \) (wrong value) and sweep \( c \). Compare the minimum χ² to the case with \( a = 0 \). What happens?
Explanation
Fixing a parameter at a wrong value constrains the optimisation. The best fit with \( a = 10 \) can only adjust \( c \) to compensate, but a constant offset can't mimic a quadratic — the residual χ² is necessarily higher. This is why automated fitting optimises all parameters simultaneously.

Playing Human Optimizer

Here's a strategy that actually works: optimise one parameter at a time. Hold \( a \) and \( b \) fixed and find the best \( c \); then hold \( a \) and \( c \), find the best \( b \); then \( b \) and \( c \), best \( a \). Repeat. This is coordinate descent — simple but effective. The explorer runs this freeze-and-optimise cycle for you: the sliders below only set the starting point; each click of "Step" then performs one full round automatically, and "Auto-Run" loops it until convergence. Watch the history panel to see the parameters take turns moving.

Interactive: Iterative Search (Coordinate Descent)
Key Insight

Coordinate descent converges quickly when the parameters are nearly independent (circular χ² contours) but slowly when they're correlated (elongated ellipses). Watch the χ² history: it drops rapidly at first, then plateaus. Automated algorithms like Levenberg–Marquardt (used by curve_fit) move in all directions simultaneously, converging much faster.

Explanation
  • False: Most algorithms (including Levenberg–Marquardt) find local minima. For non-linear models, bad initial guesses can lead to wrong answers.
  • True: Algorithms like L–M use the gradient and curvature (Jacobian/Hessian) to step in the optimal direction, not just along one axis at a time.
  • True: The covariance matrix from the fit gives parameter uncertainties automatically — a huge practical advantage.
  • False: All iterative algorithms need an initial guess. Bad guesses can cause convergence failure, which is why building intuition manually is valuable.

Python Code

Here's how to sweep parameters and implement coordinate descent in Python.

Python 
import numpy as np
import plotly.graph_objects as go

# Galileo's data: d = (g/2)t², g = 9.8
g_true = 9.8
times = np.arange(1, 11)
d_true = 0.5 * g_true * times**2

# Noisy measurements (5 trials, 15% noise)
rng = np.random.default_rng(42)
data = np.array([d_true + rng.normal(0, 0.15 * d_true)
                 for _ in range(5)])
means = data.mean(axis=0)
errors = data.std(axis=0, ddof=1) / np.sqrt(4)

# 1D sweep of parameter c (with a=0, b=0)
c_values = np.linspace(2, 8, 500)
chi2_c = [np.sum(((means - c * times**2) / errors)**2)
          for c in c_values]

# Find minimum
c_best = c_values[np.argmin(chi2_c)]

fig = go.Figure()
fig.add_trace(go.Scatter(
    x=c_values, y=chi2_c, mode='lines',
    line=dict(color='#00f3ff', width=2),
    name='χ²(c)'))
fig.add_trace(go.Scatter(
    x=[c_best], y=[min(chi2_c)], mode='markers',
    marker=dict(size=12, color='#ffff00', symbol='star'),
    name=f'Min: c = {c_best:.3f}'))
fig.update_layout(
    template='plotly_dark',
    title=f'Parameter sweep — best c = {c_best:.3f}',
    xaxis_title='Parameter c', yaxis_title='χ²')
fig.show()
Python 
import numpy as np

# Regenerate the dataset (same as Tab 1) so this script runs standalone
g_true = 9.8
times = np.arange(1, 11)
d_true = 0.5 * g_true * times**2
rng = np.random.default_rng(42)
data = np.array([d_true + rng.normal(0, 0.15 * d_true)
                 for _ in range(5)])
means = data.mean(axis=0)
errors = data.std(axis=0, ddof=1) / np.sqrt(4)

def chi2(a, b, c, means, errors, times):
    model = a + b * times + c * times**2
    return np.sum(((means - model) / errors)**2)

def optimize_1d(param_idx, params, means, errors, times):
    """Sweep one parameter, return its best value."""
    sweep = np.linspace([-30, -10, 2][param_idx],
                        [30, 10, 8][param_idx], 1000)
    best_val, best_chi2 = params[param_idx], np.inf
    for v in sweep:
        p = list(params)
        p[param_idx] = v
        c2 = chi2(*p, means, errors, times)
        if c2 < best_chi2:
            best_chi2, best_val = c2, v
    return best_val

# Coordinate descent
params = [15.0, -5.0, 3.0]  # bad initial guess
for rnd in range(10):
    for idx in range(3):
        params[idx] = optimize_1d(idx, params, means, errors, times)
    c2 = chi2(*params, means, errors, times)
    print(f"Round {rnd+1}: a={params[0]:.2f}, "
          f"b={params[1]:.2f}, c={params[2]:.3f}, χ²={c2:.1f}")
    if rnd > 0 and abs(c2 - prev_chi2) < 0.01:
        print("Converged!")
        break
    prev_chi2 = c2
