Model Selection: Simple vs Complex

You've seen that adding parameters always reduces χ² — a 5-parameter model will never fit worse than a 3-parameter one. So why not always use the most complex model available? Because extra parameters can fit noise, not physics. This section teaches you to choose the simplest model that captures the real signal — no more, no less.

Learning Objectives
  • Understand why more parameters doesn't mean a better model
  • Recognise overfitting by comparing training and test performance
  • Use χ²/dof and the BIC to choose model complexity
  • Apply the parsimony principle: simplest model that fits the data

The model selection trade-off:

$$ \underbrace{\chi^2}_{\text{fit quality}} \;\;\text{vs}\;\; \underbrace{k}_{\text{parameters}} $$

More parameters (\( k \)) always reduce χ², but each new parameter "uses up" a degree of freedom. The reduced χ² = χ²/dof (where dof = \( N - k \)) balances fit quality against model complexity. A good model has χ²/dof ≈ 1.

How Many Parameters Do You Need?

The data comes from Galileo's experiment: \( d = \tfrac{1}{2}g\,t^2 \). The true model has one shape parameter (the coefficient of \( t^2 \)). Try fitting with 1 through 5 polynomial parameters and watch χ²/dof. It starts high (underfitting), drops to ≈ 1 (just right), and then stays roughly there — the extra parameters aren't helping.

Going from 3 to 5 parameters, χ² decreases slightly — yet χ²/dof can increase. Why?
Explanation
χ² can only fall (the 3-param model is a special case of the 5-param one), but the ratio χ²/dof has a denominator too: dof drops by 2, from \( N-3 \) to \( N-5 \). If the extra parameters are only fitting noise, χ² barely moves while the denominator shrinks, so the ratio goes up. That's the quiet genius of χ²/dof — it has a built-in complexity penalty that charges one degree of freedom per parameter.

The Danger of Overfitting

Overfitting means your model memorises the noise in your training data instead of learning the underlying pattern. The telltale sign: the model fits the training data beautifully but predicts new data poorly. Watch the cyan training curve drop as you increase the polynomial degree — but the red test curve rises after the sweet spot.

Interactive: Overfitting Demonstrator
Key Insight

The right panel tells the whole story. Training error (cyan) always decreases with more parameters — more knobs to turn, better fit. Test error (red) initially decreases too, but after degree 2 it starts to rise. That's overfitting: the high-degree polynomial wiggles through the training points but wildly misses new data. The optimal model complexity is where test error is minimised — typically degree 2 for our quadratic data.

The Parsimony Principle

How do we formalise "simplest model that fits"? Two tools: χ²/dof (should be ≈ 1) and the Bayesian Information Criterion (BIC = χ² + k · ln N), which explicitly penalises extra parameters. Lower BIC = better model. Toggle the "Extra Signal" button to add a linear term \( bt \) to the true model, and watch how BIC correctly adjusts its recommendation.

Interactive: Parsimony Meter
Key Insight

With "Extra Signal: OFF" the true model is \( d = ct^2 \). BIC correctly favours a simpler model (1–2 params). Now turn it ON — the true model becomes \( d = bt + ct^2 \). BIC shifts to favour 2–3 params because the linear term is real signal, not noise. The penalty \( k \cdot \ln N \) prevents BIC from rewarding unnecessary complexity but allows it when the data genuinely needs more parameters.

What does the BIC penalty term \( k \cdot \ln N \) do?
Explanation
BIC = χ² + k · ln(N). Each additional parameter adds ln(N) to the BIC score. This means a more complex model must reduce χ² by at least ln(N) per parameter to be preferred. It doesn't always pick the simplest model — if the data genuinely needs more parameters, the χ² reduction outweighs the penalty.
Model B has one more parameter than A and lowers χ² by 1.5 (\( N = 10 \) points). Which does BIC prefer?
Explanation
BIC charges a penalty of \( \ln N \approx \ln 10 \approx 2.3 \) for each extra parameter and only credits the drop in χ². Here the gain is 1.5 but the toll is 2.3, so B's net BIC is higher (worse) than A's — BIC keeps the simpler model A. The takeaway: a lower χ² alone never settles a comparison; the improvement first has to clear the complexity penalty.

Python Code

Here's the Python equivalent for model selection analysis.

Python 
import numpy as np
from scipy.optimize import curve_fit

# Galileo data with noise
rng = np.random.default_rng(42)
t = np.arange(1, 11, dtype=float)
d_true = 0.5 * 9.8 * t**2
noise = 0.15 * d_true
d_obs = d_true + rng.normal(0, noise)

# Define models of increasing complexity
models = {
    'Linear':    lambda t, a, b: a + b*t,
    'Quadratic': lambda t, a, b, c: a + b*t + c*t**2,
    'Cubic':     lambda t, a, b, c, d: a + b*t + c*t**2 + d*t**3,
}

N = len(t)
for name, func in models.items():
    popt, pcov = curve_fit(func, t, d_obs, sigma=noise,
                           absolute_sigma=True)
    k = len(popt)
    residuals = d_obs - func(t, *popt)
    chi2 = np.sum((residuals / noise)**2)
    dof = N - k
    bic = chi2 + k * np.log(N)

    print(f"{name:10s}  k={k}  chi2/dof={chi2/dof:.2f}  BIC={bic:.1f}")
Python 
import numpy as np
import plotly.graph_objects as go
from plotly.subplots import make_subplots

rng = np.random.default_rng(0)
t_train = np.sort(rng.uniform(0.5, 10.5, 10))
d_true = 0.5 * 9.8 * t_train**2
noise = 0.15 * d_true
d_train = d_true + rng.normal(0, noise)

# Hold-out test set
t_test = np.array([2.5, 4.5, 6.5, 8.5, 10.0])
d_test = 0.5*9.8*t_test**2 + rng.normal(0, 0.15*0.5*9.8*t_test**2)

train_err, test_err, degrees = [], [], []
for deg in range(1, 9):
    coeffs = np.polyfit(t_train, d_train, deg, w=1/noise)
    poly = np.poly1d(coeffs)
    train_chi2 = np.sum(((d_train - poly(t_train))/noise)**2)
    test_chi2 = np.sum(((d_test - poly(t_test))/(0.15*0.5*9.8*t_test**2))**2)
    dof = len(t_train) - (deg+1)
    degrees.append(deg)
    train_err.append(train_chi2/max(dof,1))
    test_err.append(test_chi2/len(t_test))

fig = go.Figure()
fig.add_trace(go.Scatter(x=degrees, y=train_err, name='Train chi2/dof'))
fig.add_trace(go.Scatter(x=degrees, y=test_err, name='Test chi2/pt'))
fig.add_hline(y=1, line_dash='dash', line_color='green')
fig.update_layout(template='plotly_dark',
    xaxis_title='Polynomial Degree', yaxis_title='chi2 / point')
fig.show()
